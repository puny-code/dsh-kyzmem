# v0.13.1：本地嵌入改为可选能力（修卸载死锁）

## 问题

卸载或升级插件时，面板一直「卸载中」，随后被看门狗杀掉，留下半删的
`node_modules/onnxruntime-node`（只剩 `onnxruntime.dll` 与 `onnxruntime_binding.node`），
再次打开时插件表现为损坏。

## 根因

`@huggingface/transformers` 依赖 `onnxruntime-node`。插件加载时 eager 创建嵌入器，
宿主进程因此 `dlopen` 了 profile 里的 `onnxruntime.dll`：

- Windows 在 DLL 被映射期间拒绝删除该文件；
- Node 不会卸载已加载的原生 addon；
- 于是 pnpm 的 `remove` 必然失败 → DSH 的卸载流程超时被杀 → 已删的部分不回滚。

上游 v0.8.16/v0.9.0/v0.9.3 用的是同一份依赖和同一段 eager 初始化，所以这不是本仓
引入的问题，只是「在插件运行期间卸载」这一操作在当时没被触发过。

## 改动

1. `package.json`：`@huggingface/transformers` 从 `dependencies` 移到
   `peerDependencies` + `peerDependenciesMeta.optional`，同时保留在 `devDependencies`
   （仓库内的 e2e 测试与回填脚本要用）。默认安装不再包含 native 栈。
2. `src/embedder/local.ts`：
   - 新增 `hasTransformers()`，用 `createRequire(...).resolve()` 只解析、不加载；
   - `createLocalEmbedder()` 返回 `Promise<KyzmemEmbedder | undefined>`，模块不在时直接
     返回 `undefined`，检索降级为关键词，启动路径不下载、不加载、不报错。
3. `scripts/backfill-embeddings.mjs`：改为动态导入，缺依赖时打印安装提示并退出 1。
4. 新增 `docs/uninstall.md`：文件锁成因、正确顺序（先完全退出 DSH 再卸载）、半删
   profile 的修复命令、以及「启用可选嵌入后升级/卸载前必须先退出」的告警。
5. `tests/embedder.spec.ts`：适配可空签名；新增一条只验证探测函数返回布尔的用例。

## 取舍

- 默认安装后没有语义向量，检索是纯关键词（FTS5 + 2-gram）——这是有意的：换来
  「运行期卸载永不因文件锁失败」。想要向量的人按 `docs/uninstall.md` 自行装可选依赖。
- 安装命令不再需要 `--allow-build=onnxruntime-node --allow-build=protobufjs`；
  带上也无副作用。
- 已存在的向量数据不受影响，`attachEmbeddings`/`findContradictions` 在没有查询向量时
  自动跳过。

## 验收

`tsc --noEmit` 0 错；`vitest run --no-file-parallelism` 全绿；`check-messages` 487×3、
`check-patterns` 43/0、`measure-descriptions` 通过；`pnpm bundle` 后 `lib/index.js`
仍在 716 kB（transformers 保持外部动态导入，未被内联）；临时 profile 安装 0.13.1 后
`dsh plugin remove` 不再遇到 `onnxruntime.dll` 占用。
