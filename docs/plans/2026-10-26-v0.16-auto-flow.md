# 全流程自动化实施计划（v0.16.0 候选）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不牺牲检索效果的前提下，把冲突裁决、设置生效、安装运维、回填、死信、复习、锚点全部改为自动执行，只做可逆动作，全部可审计可撤销。

**Architecture:** 新增"自动动作层"：所有自动决策先过影子期（只记 `auto-proposed`），7 天后生效；执行时写标准 op_log；按批次 id 统一撤销。LLM 只做裁决信号源，走已有 `MemoryJudge` 接口；规则与 LLM 双轨，动作只在两者一致时才做归档。

**Tech Stack:** TypeScript（node:sqlite 同步事务）、vitest（串行 `--no-file-parallelism`）、tsdown bundle。

**Spec:** `kyzmem流程自动化方案.md`（§1–§4、§6）＋ 用户 2026-10-26 决定（总原则/冲突编排/其他环节/前置工作/LLM 选型/热更新，共 6 节）。

## Global Constraints

- 只做可逆动作（archive、边、排期），永不物理删除。
- 凡改变排序或可见性的改动，必须跑 `tests/rank-regression.spec.ts` 与 `tests/query-recall.spec.ts`，召回不得下降。
- 所有自动动作写 op_log，detail 含 rule id、阈值、相似度、左右 id、批次 id、版本号。
- 禁止：7B 自动 outcome、8A 默认开启摄取、5C 调用宿主重载。
- LLM 失败 → 降级为规则或仅提示，不得中断流程。
- 不引入新云依赖；`judge.model` 为空即用默认对话模型，不可用时回退默认模型。

## Phase 1 — 冲突自动裁决

### Task 1.1 规则裁决函数（严格阈值）

**Files:**
- Create: `src/automation/conflict-rules.ts`
- Test: `tests/automation-conflict-rules.spec.ts`

**Interfaces:**
- Consumes: `ConflictPair`（`store.listConflicts` 返回项）。
- Produces: `ruleVerdict(pair) → { action: 'archive-left'|'archive-right'|'none', ruleId }`。

规则：R1（`r-tier`：一方 user-confirmed 另一方低 tier → 归档非确认方）；R2（`r-newer`：同 scope＋同 kind（仅 preference|decision）＋实体交集非空＋年龄差 ≥30 天＋新者 importance/confidence 双高且差值 ≥0.15 → 归档旧者）；其余 `r-abstain`。

- [ ] **Step 1–5**: 三分支测试→实现→通过→Commit。

### Task 1.2 接线 MemoryJudge（默认对话模型 + judge.model）

**Files:**
- Create: `src/automation/judge.ts`
- Modify: `src/config.ts`（`judge.model` 可选键＋`CONFIG_KEYS`）、`src/index.ts`（装配 judge，注入 `ingest/hook.ts:202` 与 `tools/create.ts:61` 的 `judge?` 槽位）
- Test: `tests/automation-judge.spec.ts`

**Interfaces:**
- Consumes: `src/llm/client.ts` 的 `streamText`（实现时核对签名）；`MemoryJudge`（`write-disposition.ts:57`）。
- Produces: `buildJudge(opts)`；`resolveJudgeModel(configured, defaultModel)`（空→默认；不可用→回退默认＋op_log）。

阈值初值：`deferMergeAbove=0.9`、`deferAcceptBelow=0.15`、`contradictMinProbability=0.9`。同一 state 两种提示词各判一次，一致才算数；失败→无判断（调用方纯规则降级，已有行为不动）。

- [ ] **Step 1–5**: 一致/不一致/失败三路测试→实现→通过→Commit。

### Task 1.3 自动裁决编排

**Files:**
- Create: `src/automation/conflict-auto.ts`
- Modify: `src/maintenance/scheduler.ts`、`src/store/sqlite.ts`（归档＋建边，复用现有语义）
- Test: `tests/automation-conflict-auto.spec.ts`（另跑 `rank-regression`＋`query-recall`，召回不降）

编排：规则与 LLM 同归档 → 归档输家＋`supersedes` 边（批次 `auto-conflict-<yyyymmdd>-<seq>`）；不一致 → 保持现状；仅 LLM 矛盾 → 只建 `contradicts` 边；LLM 判无 → 不建边。防线：日归档 ≤5（`MAX_AUTO_ARCHIVE_PER_DAY=5`）；trailing 20 次不一致率 >40% 降级只标注，≤20% 恢复。

- [ ] **Step 1–5**: 四格＋上限＋降级测试→实现→通过（含基线）→Commit。
