# v0.11.0 — 批一~批五 + 度量（2026-10-21）

依据：`dsh-engram改造计划.md`（v0.10.0 已落地「批零」）。本版把剩余批次一次性做完，
并把「记忆宫殿」时代的命名与文档收尾为 `dsh-kyzmem`。

## schema v15（一次迁移）

`nodes` 新增 5 列：`invalid_at`（失效时刻）、`expires_at`（TTL）、`source_tier`（来源分级）、
`last_retrieved_at` / `last_reviewed_at`（拆时钟）。新增索引 `nodes_invalid`、`nodes_expires`。
旧库从 v14 自动升到 v15，迁移前仍先生成 `.pre-migration` 快照。

## 批一：写入把关与时效

- 写入四态补齐：`drop` 新增 `near-duplicate`（跨 kind 且最近邻余弦 ≥ 0.98；同 kind 的 ≥0.92
  由 merge 先接走），与既有的 `chitchat` / `exact-duplicate` 一起强制落 `op_log('drop')`。
- `invalid_at`：`update` / `supersedeMany` 给旧条打失效点，检索默认只搜未失效条目；
  `kyzmem_search` 新增 `asOf` 时点检索。
- 拆时钟：检索命中只更新 `last_retrieved_at` 与 `access_count`，复习/回报只更新
  `last_reviewed_at`；`setStatus`/`forget`/`restore` 不再顺手改时间戳。
- proof 权重默认 0.1 → 0.05（实测 `access_count` 中位为 0，旧权重只在放大少数老条目）。

## 批二：渐进披露与分层注入

- `kyzmem_search` 新增 `mode` 三档：`index`（默认，只给 id/ref/房间#桩位/日期/门牌/线索，
  不回正文）、`timeline`、`full`。正文上限进配置：`recallPerItem=160`、`recallTotal=4800`。
- 证据门控制面（「作答前先调用 kyzmem_assess」）移出 `<memory_context>` 标签，不再与证据
  抢注意力；去重键改为「批次 id + 待判定批次数」。
- `kyzmem_assess` 判定 sufficient 且引用非空时，被引条目 confidence +0.02（不动 access_count），
  强化结果落 `op_log('assess-reinforce')`。

## 批三：后台整理（欠账偿还，不绑钟点）

- 删除两个「每 24 小时」定时器，改为按欠账触发的状态机：启动后 `setImmediate`、
  会话结束、每步首帧、面板 `/health` 都能踢一次；单次预算
  `{1500ms, 50 条, 1 次辅助 LLM}`，任务轮转 decay → merge → refurb。
- 单飞租约 `maintenance-lease`（5 分钟），starvation 保护（超 7 天强制小轮），
  空档期减载（距上次活跃超 7 天：decay ≤100、pending ≤3、consolidation ≤50）。
- 闭馆整理扩到全部 `project-*.db`；门槛「active ≥ 5 且同 kind ≥ 3」；已有向量不重算。
- 摄取 pending 死信：进度写回 `{attempts, firstAt}`，失败累计，3 次进死信；
  只有确认写入成功才清键；不可解析的键满 30 天出队。
- SM-2 逾期超 30 天的条目，答对也从 1 天重新开始（relearning）。
- due 行提示「今日待回忆 N 条（kyzmem_review_queue）」。

## 批四：多策略检索

- 两段式候选：FTS 先取 256 条，向量道只在候选内算余弦；FTS 零命中回退全池。
- 每条命中带 `channels` 统计（fts / vector / graph 的耗时与命中数）落 `op_log`，面板出
  「检索通道」表。
- 默认 scope 收敛到单个 `resolveDefaultScope(hasCwd)`，工具与 39 条面板路由共用。

## 批五：纠错、审计与导出

- `purge()` 补删 `nodes_revisions`（旧版遗留）；新增 `purgeOne(id)` 单条硬删（节点 + FTS +
  修订 + 全部边，`op_log` 留墓碑）。
- 冲突终于有出口：`GET /api/kyzmem/conflicts` 列出待裁决对，
  `POST /api/kyzmem/conflicts/resolve` 支持 keep-left / keep-right / keep-both / drop-both。
- `kyzmem_forget` / `kyzmem_audit_forgotten` 输出补「删错了可在面板重开（恢复）」。
- 导出前若库内仍有未脱敏敏感词命中，显式警告而不是静默导出。

## R1~R4

- **R1 采用率**：每次检索落 `op_log('recall')`，下一轮检查模型是否引用了这些 id（或调用
  assess/examine），落 `recall-used` / `recall-ignored`；面板给近 7 天采用率。
- **R2 TTL**：`ttlFactDays=180 / ttlEpisodeDays=90 / ttlDecisionDays=365 / preference|skill=0`，
  写入算 `expires_at`，检索降权不硬过滤（×0.5 并标 `[已过期]`），画像注入跳过过期条目。
- **R3 噪声回归**：`tests/rank-regression.spec.ts` 固定 20 条中/英/代码标识符查询，
  断言每条查询的 top-3 必含期望条目。
- **R4 来源分级**：`user-confirmed / agent-inferred / tool-output / web-content`；
  检索行标 `[未确认:tool]`、`[未确认:web]`；画像默认只注入前两类；面板「仅看已确认」过滤。

## 实现偏差与取舍（照实记录）

1. **合并优先于丢弃**：契约写「同 kind 且 ≥0.98 才 drop」，但同 kind 的 ≥0.92 已被 merge 截走，
   那条分支不可达。落地为「MERGE 优先 → 跨 kind ≥0.98 才 drop」，drop 因此有了真实落点。
2. **`confirmedOnly` 是严格口径**：只回 `source_tier='user-confirmed'`。显式保存
   （`kyzmem_save`）写入该 tier；自动摄取按 `classifyIngestSourceTier` 判为
   agent-inferred / tool-output / web-content。`injectTiers` / `isTrustedTier` 管的是「注入时信不信」，
   范围更宽（含 agent-inferred），两套阈值不混用。
3. **`facts` 表不含 `source_tier`**（v15 范围外）：`kyzmem_facts` 的实体事实链是独立表，不进
   memories 列表，也不参与 `confirmedOnly` 过滤；为它加列需再起一次迁移，收益不抵风险。
4. **整理复用已有向量**：给 store 补了 `embeddingsFor(ids)`，整理只对向量缺口调 embedder；
   `src/consolidation/run.ts` 用鸭子类型探测，老 store 或测试替身缺该方法时退回重算。
5. **额外审计 op**：`ingest-pending-cleared`（`no-such-turn` 清 pending 留痕）、`active-day`
   （记录当天活跃，供空档期减载判断）；`purgeOne` 的墓碑 op 为 `tombstone`。
6. **R1 采用率的判定**：下一轮首帧比对上一轮 assistant 文本是否出现 `recall` 批次里的 id，
   或本轮调用了 `kyzmem_assess` / `kyzmem_examine`，否则记 ignored。这是启发式，不保证精确。
