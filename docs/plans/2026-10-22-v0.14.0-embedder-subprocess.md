# v0.14.0：嵌入模型移入子进程（恢复默认语义检索）

## 背景

v0.13.1 把 `@huggingface/transformers` 改成可选 peer，绕开了 `onnxruntime.dll` 的文件锁，
代价是默认没有语义向量。这个代价不可接受：卸载死锁的根因是「DLL 被哪个进程加载」，
不是「插件要不要嵌入」。

## 做法

模型跑在独立子进程里，宿主进程从不 `dlopen` 原生库：

```
宿主进程 (dsh-kyzmem)
  └─ spawn node scripts/embedder-worker.mjs <cacheDir> [remoteHost]
       └─ import('@huggingface/transformers') → onnxruntime.dll（只在这里）
```

- `scripts/embedder-worker.mjs`：stdin/stdout 按行 JSON 协议，命令 `{id,texts}` /
  `{cmd:'close'}` / `{cmd:'ping'}`，回复 `{type:'ready'|'fatal'}`、`{id,vectors:[base64]}`。
  向量走 base64 float32（512 维 = 2 KB），IPC 开销可忽略。
- `src/embedder/local.ts`：`WorkerBackedEmbedder` 负责 spawn、就绪握手、按 id 匹配响应、
  超时（首轮 10 分钟含下载）、崩溃后下次调用自动重启；`close()` 发 close 再等 2 秒，
  超时 kill。
- `src/index.ts`：`ctx.effect(() => async () => { await current?.close() })`——cordis 的
  disposer 会被 await，DSH 卸载流程（`selectBundle(false)` + `reload()`）因此保证在
  `pnpm remove` 之前杀掉子进程。
- 宿主进程被强杀时 stdio 管道断开，worker 自行退出，不留持锁孤儿。

## 与 v0.13.1 的取舍对比

| | 0.13.1（可选 peer） | 0.14.0（子进程） |
|---|---|---|
| 默认语义检索 | 无 | 有 |
| 运行期卸载 | 安全 | 安全（dispose 杀子进程） |
| 安装体积 | 小 | +约 200MB（onnxruntime 原生库） |
| 安装参数 | 不需要 `--allow-build` | 需要（pnpm 11 拦截构建脚本） |
| 进程模型 | 无额外进程 | 多一个常驻子进程 |

## 验证

1. worker 直连：`ready` → 单条文本 → `dims=512`、`bytes=2048`、`norm=1.0000`、耗时约 1.1s（缓存命中）。
2. 父模块：`createLocalEmbedder` 961ms、两条文本 512 维、`close()` 后 `handles freed`。
3. **锁隔离**：在装了 0.14.0 的临时 profile 里，父进程存活期间删掉
   `node_modules/onnxruntime-node` 成功 → 证明父进程没有映射 `onnxruntime.dll`；
   worker 退出后 `dsh plugin remove` 2s、exit 0、目录清空。
4. 门禁：tsc、串行 vitest、三语检查、bundle、`npm pack`。

## 已知限制

- 子进程常驻内存（模型 + 运行时），首次使用要下载权重。
- 升级 `dsh-kyzmem` 自身时，旧 fiber 仍在运行，`pnpm add` 不会先卸载它；由于
  transformers 一直是 dependency，升级路径不会删除该目录，不触发锁。
- 若在极端的「运行中手动删除 profile 的 onnxruntime-node」场景仍可能失败，属于用户
  绕过包管理器的操作，文档里说明先退出 DSH。
