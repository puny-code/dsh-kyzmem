# v0.15.0 运维页设置卡片（可视化修改插件配置）

## 目标
在「天枢」运维 tab 顶部加设置卡片，让用户不改 cordis.yml 也能调整插件配置。

## 已核实的宿主事实
- 宿主配置写回走 cordis 内部 loader 钩子（`internal/update` → `entry.update` → `tree.write()`）。插件不应直接调用这条内部路径。
- `apply(ctx, config)` 在加载时把 `resolveConfig(config)` 一次性固化；约 100 处 `resolved.*` 读取都是加载期快照。
- 因此「热更新」需要重启插件才能生效。卡片必须明确告知。

## 方案
1. 插件自有覆盖文件 `<dbDir>/settings.json`（不碰宿主配置）。
2. `apply()` 先读 `settings.json`，与宿主 config 合并（覆盖文件优先）后再 `resolveConfig`。
3. 新增 `GET /api/kyzmem/settings`（返回当前生效值 + 覆盖标记 + 可编辑字段元数据）与 `POST /api/kyzmem/settings`（校验后原子写入覆盖文件）。两者都走 loopback 与 `guardWrite`。
4. 面板运维 tab 顶部新增 `SettingsCard`：分组表单（摄取/辅助模型/后台整理/检索召回），保存时明确提示「需重启插件生效」。
5. 写入前复用 `resolveConfig` 做校验，错误原样回显。

## 验收
- 单测：覆盖文件合并优先级、非法值拒绝、原子写入、未知键拒绝。
- 路由测：GET 返回值与当前生效值一致；POST 缺 Origin 或错误 Content-Type 被拒。
- 三语文案键齐。

## 落地（v0.15.0）

- `src/settings-overlay.ts`：覆盖层读写。`readOverlay` 文件缺失返回 `{}`、内容损坏抛错（由 apply 告警降级）；
  `mergeWithOverlay` 覆盖层优先且拒绝改 `dbDir`；`saveOverlay` 只接受 `CONFIG_KEYS` 内的键、先用
  `resolveConfig` 试算、`null` 表示清除覆盖、写盘走临时文件 + rename；`describeEffective` 把解析后的
  `maintenance.*` 压平成卡片能直接读的六个字段。
- `src/index.ts`：`apply()` 先算 `dbDir`，读覆盖层并告警降级，再合并 → `resolveConfig`。配置一次加载固化，
  所以卡片提示「重启后生效」，没有假装热更新。
- `src/routes.ts`：`GET /api/kyzmem/settings` 返回 `{ values, overridden, restartRequired }`；
  `POST` 过 `guardWrite` + `readJsonBody`，非法值原样回 400。
- `src/client/KyzmemPanel.tsx`：运维 tab 顶部 `SettingsCard`（摄取 / 检索召回 / 后台整理三组），
  草稿只提交改动过的键，要求回到默认时发 `null` 清除覆盖；`重置为默认` 一次清空全部覆盖。
- 三语各新增 29 个键（`check-messages` 488×3）。
- 测试：`tests/settings-overlay.spec.ts` 12 例（合并优先级、dbDir 保护、未知键、非法值、null 清除、
  原子写入、损坏文件 loud 失败、扁平化）。
- 门禁：tsc 0 错；串行全量 647 passed / 1 skipped（43 文件）；check-patterns 43/0；measure 通过；
  bundle host 726.70 kB / client 285.48 kB。

## 已知边界

- 保存后需要重启插件或 DSH 才生效（插件没有安全的自我热重载入口）。
- 卡片只覆盖六个高频旋钮；`provider`/`model` 与 `dbDir`/`modelCacheDir` 这类基础设施项仍走配置文件。

## v0.15.1（设置卡片显示现状）

用户反馈：卡片里看到的永远是默认值，看不出当前实际配置。核对后发现宿主 `cordis.yml` 是空列表、
`~/.dsh/kyzmem/settings.json` 不存在——默认值确实就是当时的生效值，卡片没有读错，但它只说了
「是否被覆盖」，没说明来源，也没给出全貌。

- `GET /api/kyzmem/settings` 增加 `snapshot`（解析后所有标量字段摊平）、`sources`（每个键：
  覆盖 / 配置文件 / 默认）、`settingsPath`、`hasOverlay`。
- 卡片每个字段的来源标记改为三态（设置覆盖 / 配置文件 / 默认值）；底部新增只读「当前生效值」表，
  逐项列出键、值与来源；没有覆盖时明确写「尚未保存任何覆盖，以下全部是默认生效值」。
- `src/settings-overlay.ts` 新增 `flattenResolved` 与 `sourcesFor`；嵌套字段（maintenance）单独摊平，
  对象字段不进表格。
- 测试补到 13 例（来源标注、快照只含标量）。
