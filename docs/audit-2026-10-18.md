## 0. 总评

**先说资产**（迭代中不要丢）：

1. **领域设计**——学习核心隐喻（房间/铭牌/参观/闭馆/蒸馏）贯穿产品、代码与文案，同类项目里少有的产品想象力；
2. **测试文化**——463 个测试 / 33 个 spec / `strict + noUncheckedIndexedAccess` / 三语键配平与密钥清洗验收脚本，测试:源码比 0.44，composition.spec 是真 HTTP 全链路集成测试；
3. **安全姿态**——密钥三层脱敏（PEM/Bearer/sk-/ghp_/AKIA + 语言标签 + 用户词表）、全 SQL 参数化、回环三重防线、64KiB body 上限、零 innerHTML，经两轮外部评审验证；
4. **文档诚实度**——README 双语 54KB，明确声明哪些检查只能在 harness 工作区跑，known limitations 不藏；
5. **事故学习闭环**——修复都带回归语境注释（pollFailed、SKIP_KEY、EMPTY_PREVIEWS 兜底注释直接点名错误边界教训）。

**核心短板一句话**：单点打磨密度高，但**系统性质量缺位**——错误路径普遍被吞掉或伪装成「健康空态」、渲染异常被宿主 slot 错误边界放大成整面板白屏且无恢复 UI、客户端/服务端契约无版本防护、交付管线（lint/coverage/发布冒烟）几乎不存在。用户说「提升空间很大」，感知来源主要就是这些。

**如果只修五件事**：

1. 面板自愈：插件级 ErrorBoundary（按视图降级 + 重试按钮）+ 视图 loading/error/empty 三态强制分离 + 版本握手横幅——把整类白屏从「不可见事故」变成「可见警告」（§1.1、§2.1）；
2. 数据安全：restore 后关闭并失效分库缓存（当前**恢复后写入落旧文件、静默丢失**）+ SQLite 开 WAL/busy_timeout + 迁移前自动快照（§1.2）；
3. 摄取重放循环逐键隔离 + 失败放弃策略 + LLM 已付费成果不丢弃（§1.3）；
4. i18n 三修：服务端文案语言与面板语言解耦、俄语复数、硬编码中文退出数据层（§6）；
5. 交付管线：打包冒烟进 CI + release 脚本 + tag/Release 规范化（§7）。

## 1. 稳定性与数据安全（最高优先）

### 1.1 崩溃放大面——白屏是常态结局（P1）

- **面板无自身 ErrorBoundary**（全 client grep 零命中）。宿主 slot 的错误边界行为 = 任何子组件抛错 → 整面板卸载 → 空白，无报错无重试。v0.8.15 白屏事故已实锤此机制。
- **列表行渲染是最大脆弱面**（P1）：`KyzmemPanel.tsx:3325` `record.status.charAt(0)`、`:3330` `content.includes`、`:3344-3346` `importance.toFixed(2)`——直接对未校验服务端字段调方法（TS 断言无运行时保护）。一行坏数据 = 陈展整页崩。同款模式在 ReviewBody:737-741、EditForm:823。**修复**：入口 `normalizeMemoryRow()` 收敛类型，坏行丢弃计数（store 层 rowToRecord 已是正确范式）。
- **修复方向**：每个 tab 内容包一层 ErrorBoundary → EmptyState 风格「该视图渲染失败 · 重载」按钮；新增响应字段一律 optional + 兜底，写进贡献约定。

### 1.2 数据安全——两处 P1 级隐患（代理新发现，未公开过）

- **F16 · restore 备份后写入落旧文件（数据丢失）**：`backup/tar.ts:123-134` 把旧 `user.db` rename 走再搬入新文件，但 `index.ts:530-551` 的 stores Map 缓存连接仍指向旧 inode——「恢复成功」后面板读旧库、新写入进 `.before-restore-*` 文件，**重启后这些写入静默消失**。修复：RouteDeps 注入 `closeAllStores()`，restore 后关闭全部分库并清缓存。
- **F15 · 无 WAL / busy_timeout**：`store/sqlite.ts:379-393` 打开连接零 PRAGMA。所有 DSH 进程共用全局 `~/.dsh/kyzmem` 库，默认 rollback journal + 无 busy 等待 → 双窗口并发写立刻 SQLITE_BUSY（摄取/衰减/面板 500 全可触发，24h 定时任务必然周期撞车）。修复：`PRAGMA journal_mode=WAL; PRAGMA busy_timeout=5000; PRAGMA synchronous=NORMAL`，两行收益极大。
- **F17 · 迁移无快照 + 打开失败被永久缓存**：迁移前无自动备份（v12→v13 是改行数据迁移，出错不可逆）；`versionRow === undefined` 直接盖当前版本号（meta 损坏的旧库会跳过全部迁移）；`index.ts:549` 先 set 后 await——打开失败的 rejected promise 永久缓存，盘上修复了进程内也无重试机会。
- **F18/F19 · 备份撕裂与 Zip Slip（P2）**：备份直接 readFile 热文件（应 `VACUUM INTO`）；extractTar 成员名未净化（`../../` 可写出目标目录）。
- **F26 · restore 路径校验在 Windows 恒失败（P2）**：`routes.ts:871` `startsWith(dbDir + '/')` 在反斜杠平台永不匹配 → Windows 上一律 400。用 `relative()` 判定。

### 1.3 摄取管线——已付费成果被丢弃（P1）

- **F11 · pending 重放循环无逐键隔离**（`ingest/hook.ts:761-790`）：①队头阻塞——#1 失败 #2..N 全不试；②无限重试——失败键不清除，每个会话启动重来；③路由过期放大——重放只用 `resolved.routeOverride` 不回退 `preStepState.route`（历史回填做了回退，这里是兄弟缺口）。修复：逐键 try/catch + attempts/年龄字段（超 7 天或 3 次放弃并落审计）。
- **F12 · LLM 已付费、成果永久丢弃（P2）**：replay 中 unparseable-output 时函数返回不抛 → pending 被清掉，专为补救重付的调用白费且无审计。
- **F13 · 批内一处抛错弃掉整批后半（P2）**：候选循环 embed/write 无逐条容错。

### 1.4 已实锤的现场事件（本轮走查）

- **白屏事故**（v0.8.15 混合版本）：RefurbCard 读新响应字段无兜底 → TypeError → 整面板卸载。修复已在工作区（未发布），机制见 §2.1。
- **走廊鸟瞰卡死**：UI 停在「加载走廊鸟瞰…」>9s 不落地。triage 结果（当日）：后端无罪——对运行中的旧后端实测三种参数变体全部 200/<14ms；前端路径是纯 fetch→setGraph，无悬挂点。最可疑因素是走查当时宿主面板激活态漂移（S4）+ 整机负载 8+；需干净环境复现后再定位，未做投机性修复。
- **「回忆螺旋」疑似渲染挂起**：连续三次独立尝试打开该页签均 32s 超时（同时段其余页签正常打开），疑似螺旋布局/动画死循环或重渲染，需隔离复现。
- **面板激活态漂移**（宿主侧）：Memory Palace 激活数秒后两次被自动切回 FDE 工作台（无用户操作）——需与宿主仓库协同排查。

## 2. 客户端/服务端契约（版本偏斜防护，P1 体系）

- **无版本握手**：偏斜只能靠用户踩坑发现。插件 VERSION 常量甚至停在 `0.7.6`（`src/index.ts:62`，注释称与 package.json 同步，实际 0.8.15）——备份 `_meta.json` 已记错版本。
- **修复三件套**：① `GET /version` 返回 `{server, client}`，不一致时面板顶部黄色横幅「面板与后端版本不一致，请重启应用」——把整类 P0 变成可见警告；② 响应契约收敛到单一 `contract.ts`，新字段必须 optional 至 N-1 版本；③ 构建期从 package.json 注入版本号（tsdown define），删手写常量。

## 4. 用户体验一致性

- **U1 失败伪装三兄弟（P1）**：LogPanel `.catch(()=>setRows([]))`（:1150，审计日志挂了显示「无活动」）、RefurbCard（:1316，故障显示「宫殿健康 0 建议」）、TourProposalCard（:1235，失败显示假空宫殿问候）。对照主列表与 spiral 已正确区分 error/empty——**补齐即可，范式已有**。
- **U2 破坏性操作三种确认标准（P2）**：refurb 用 `window.confirm`（原生弹窗）、批量遗忘用两段式按钮（最佳实践）、列表单条遗忘**零确认**。且遗忘完成无「撤销」toast（restore 能力存在但要用户自己发现）。
- **U3 搜索框 trim bug（P2，一行修复）**：`onChange` 即时 `.trim()`（:3236、:1886）——用户**永远打不出含空格的查询**。
- **U4 useToast 返回值不稳定（P2）**：每次渲染新对象，而 HistoryBackfillCard 等把 toast 当 effect 依赖——每次 toast 出现都触发重估/重拉/轮询器重建。
- **U5 EditForm 保存无 busy 防重（P2）**：双击双写；批量遗忘逐条失败不报告。
- **U6 dueOnly 筛选与分页错位（P2）**：页内过滤 + 全量分页 → 可出现假的「0 条」空页。
- **U7 首跑无 onboarding（P3）**：空宫殿让用户「调用 kyzmem_save」（对用户说工具名），真正的冷启动入口（历史回填）埋在运维页第三张卡。

## 5. 可访问性（对标 WCAG 2.1 AA）

- **A1 段控选中态无语义（P2）**：scope 三宫格/状态/排序（:3105、:3238、:3260）裸按钮无 `aria-pressed`；对照 kind chips 有——同一产品三种写法。
- **A2 `role=tab` 无键盘方向键（P2）**：四处 tablist 语义承诺未兑现（AT 用户会尝试方向键）。要么补 roving tabindex，要么降级 aria-pressed。
- **A3 SVG 图仅鼠标可达（P2）**：户型图房间 `<g onClick>` 无 tabindex/role；关系图节点选中无键盘等价。
- **A4 Drawer 无 Esc、无焦点管理（P2）**；ExportMenu 半成品 menu 语义（P2）。
- **A5 触达目标（P2/P3）**：写操作按钮 22-24px（`.refurbExec`、批量条），低于 24px 底线（WCAG 2.5.8）。
- **A6 亮点**：focus-visible 覆盖面广、prefers-reduced-motion 全局关停（CSS 侧教科书式）、Toast aria 就位——基线比多数项目好，缺的是上面这些一致性收尾。

## 6. 国际化（三个 P1，实锤）

- **I1 服务端文案语言冻结**：`config.ts:344` 进程启动时固化 language → `setMessageLanguage` 每进程一次 → refurb reason 等以进程语言生成（实机截图：中文 UI 出英文理由）。修复极小：refurb 路由接 `lang` 参数（`messageIn` 本就支持任意语言）；彻底方案：reason 返回 `{rule, params}` 由客户端本地化。
- **I2 俄语复数系统性错误**：`makeT`/`fill` 只做 `{param}` 直替无 ICU plural，ru 约 20 条 `{n}` 串只有一种词形（`{n} предложений` 在 n=1 时语法错误）。修复：极简 `plural(lang, n, forms)` helper，先修高频键。
- **I3 硬编码中文进数据层**：`execute()` 把 `reason:'翻新清单降级'` 等中文面值写进 POST body / op_log——EN/RU 用户存储与显示都是中文，且污染审计数据。改稳定枚举 + 显示层词典映射。
- **I4 日期格式四套来源**（P2）：`navigator.language`、无参 `toLocaleDateString`、手拼 ISO 并存——面板切 EN 后日期仍可显示中文格式。统一 `makeFormatter(lang)`。
- **I5 服务端错误串英文直出（P2）**：`'q required'`/`'unknown route'` 等经 `loadFailed: '访客受挫：{msg}'` 拼成混排。
- **I6 参数漂移无检测（P3）**：三语键齐平有编译保证，但值内 `{param}` 名单无校验——加一个 10 行的 vitest 即可封死。

## 8. 性能

- **P1** 回忆螺旋渲染挂起（§1.4，需隔离定位——疑似布局/动画循环）。
- **P2** 水印两层 `blur(40px/48px)` + 20s 无限动画：长列表滚动时合成代价叠加（reduced-motion 已覆盖，普通用户恒开）。

## 9. 安全

- **核心面干净**（维持既有结论）：密钥三层脱敏且掩码出进程、全 SQL 参数化、SSRF 面有协议白名单、XSS 零 innerHTML、tar 实现自带上限。
- **新增待修**：F19 Zip Slip（P2，恢复共享备份是合理用户行为）；F26 Windows restore 恒 400（P2，fail-closed 但功能性损坏）；`hfEndpoint` 权重作为 ONNX 执行，文档应标注「镜像需可信」；api() 对非 2xx 先 json() 导致代理错误页显示为 `Unexpected token <`（P3，先判 `response.ok`）。

## 10. CSS 与 React 架构（常态化重构项）

- **主题缝隙（P2）**：`--room-*` 暗色变体跟 OS `prefers-color-scheme` 而面板其余颜色跟宿主主题——宿主切暗 + OS 亮时对比度可能破裂；TSX 侧 `KIND_PALETTE`/`ENTITY_DOT` 完全不感知主题；**双源色板漂移**：CSS `--room-fact:#3b6ef5` ≠ TSX `'#5b8def'`——同一 kind 两种颜色。修复：TSX 读 `var(--room-*)`。
- **断点基于窗口（P2）**：960/720 两个窗口断点，宽窗口窄面板时永不触发 → 改 `container-type: inline-size` + `@container`。
- **3546 行单文件 27 组件（P2）**：数据获取模式复制 15 遍——`useApi(path, deps)` hook 可删约 300 行；按 tab 拆文件。
- **渲染期写模块级全局（P2）**：`activeProjectSelector`（:2899）并发渲染不纯，正解是 context/props 下传。
